# Security Policy

## Supported Versions

Security updates are provided for the current version of the project on the `main` branch.

| Version | Supported |
| ------- | --------- |
| Current `main` | Yes |
| Older versions | No |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues.

Report suspected vulnerabilities through GitHub Private Vulnerability Reporting for this repository. If private reporting is unavailable, open a private security advisory from the repository's **Security** tab.

When reporting a vulnerability, include as much detail as possible:

- A clear description of the issue
- Steps to reproduce the vulnerability
- Affected files, routes, or dependencies
- Potential impact
- Any suggested fix, mitigation, or relevant references

## Response Expectations

Maintainers will review security reports as soon as practical. Expected handling:

- Acknowledge receipt after the report is reviewed
- Assess severity and reproducibility
- Coordinate a fix before public disclosure when appropriate
- Credit the reporter if requested and appropriate

This is a personal open-source project, so response times may vary.

## Security Updates

Security fixes are released through normal repository updates. Users should track the latest `main` branch or the latest published release.

## Scope

This policy covers the application source code, build scripts, GitHub workflows, and project dependencies in this repository.

Out of scope:

- Vulnerabilities requiring physical access to a user's device
- Issues caused by a user's browser extensions, local environment, or modified builds
- Social engineering or phishing attempts
- Denial-of-service testing against hosted deployments
